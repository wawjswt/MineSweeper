# 战术扫雷：肉鸽模式设计规格

## 目标

在现有扫雷应用中新增一个独立的“战术扫雷”模式，把经典扫雷的确定性揭示、标记和洪水展开作为基础，加入五层短局肉鸽流程、生命值、能量、主动工具和三选一强化。经典扫雷、偏移扫雷、Hex 扫雷、环形棋盘和数独扫雷的规则与入口保持不变。

## 设计边界

- 新模式的内部标识为 `rogue`，显示名称为“战术扫雷”。
- 新模式使用固定五层流程：准备局 → 关卡进行中 → 奖励三选一 → 下一关；第五层通关后结束本局。
- 每局开始时拥有 3 点生命值，生命归零才失败；踩雷不会立即结束关卡。
- 每次踩到未处理的雷会扣 1 点生命，并将该雷标记为已拆除；同一颗雷不再重复造成伤害。
- 清空所有安全格即可通过当前关卡；未处理的雷不要求玩家全部揭开。
- 第一版不加入动态雷区、商店、金币、Boss、地图分支、持久化成长、排行榜、种子、回放或页面暂停。
- 刷新页面不保存肉鸽局；刷新后回到准备局。
- 肉鸽模式使用标准随机生成与首次点击安全规则，不复用经典模式的可推理生成选择。

## 关卡与难度

五层参数固定在 `src/rogue-level.js`，便于测试和后续平衡调整：

| 层数 | 棋盘 | 雷数 | 设计意图 |
| --- | --- | --- | --- |
| 1 | 7×7 | 8 | 教学层，熟悉生命和工具 |
| 2 | 8×9 | 13 | 扩大搜索范围 |
| 3 | 9×10 | 19 | 增加标记与能量规划压力 |
| 4 | 10×12 | 28 | 高压层，要求组合使用工具 |
| 5 | 11×14 | 40 | 最终层，检验整局强化选择 |

每层首次揭开沿用当前经典扫雷的首点及邻域安全约束。棋盘格保留 `mine`、`count`、`revealed`、`flagged`、`questioned` 等现有基础字段，并增加：

- `neutralized`：雷已经被拆除或因踩雷失效，不再造成伤害。
- `exploded`：本次操作触发了该雷，用于一次性反馈样式。

雷的数字统计始终按原始雷区计算；`neutralized` 不改变相邻数字，避免线索在玩家操作后漂移。

## 肉鸽运行状态

`src/rogue-state.js` 提供纯状态工厂和状态更新辅助函数，不直接操作 DOM。运行状态结构如下：

```js
{
  modeKey: "rogue",
  status: "ready" | "playing" | "reward" | "won" | "lost",
  floor: 1,
  totalFloors: 5,
  lives: 3,
  maxLives: 3,
  energy: 2,
  maxEnergy: 3,
  safeRevealStreak: 0,
  score: 0,
  upgrades: [],
  nextLevelToolBonus: {
    scoutPulse: 0,
    defusalKit: 0,
    reactionShield: 0,
  },
  level: {
    rows: 7,
    cols: 7,
    mines: 8,
    board: [],
    started: false,
    ended: false,
    safeCellsRemaining: 0,
    activeToolUses: {
      scoutPulse: 1,
      defusalKit: 1,
      reactionShield: 1,
    },
    shieldActive: false,
  },
  rewardOptions: [],
  notice: "",
  focusedCell: [0, 0],
}
```

状态转换规则：

1. `ready` 创建第一层，第一次揭开后变为 `playing`。
2. 安全揭开会减少 `safeCellsRemaining`，并在本次操作成功时增加 `safeRevealStreak`。
3. `safeRevealStreak` 达到 4 时增加 1 点能量，随后清零；能量不超过 `maxEnergy`。
4. 踩到雷时，如果有 `shieldActive`，消耗护盾且不扣生命；否则扣 1 点生命；两种情况都会将雷设为 `neutralized`，并清零连续揭开计数。
5. 生命变为 0 时进入 `lost`，当前层和本局不可继续操作。
6. `safeCellsRemaining` 变为 0 时，若还有下一层则进入 `reward`；第五层则进入 `won`。
7. `reward` 状态只允许从三个选项中选择一个；选择后应用强化，创建下一层并回到 `playing`。

分数只用于本局反馈，不参与胜负或随机性：每揭开一个安全格加 1 分，因工具或踩雷拆除一颗雷加 3 分，通关一层加 10 分。

## 主动工具与能量

每层开始时获得三种工具各 1 次使用额度；工具额度只对当前层有效。能量跨层保留。工具必须先选中，再点击合法目标；取消工具不会消耗能量或次数。

### 侦察脉冲

- 能量消耗：1。
- 使用额度：1 次/层。
- 目标：一个未揭开的 3×3 区域中心格。
- 效果：显示该区域包含的原始雷数和区域坐标，不揭开任何格，不改变棋盘状态。
- 非法目标：区域越界或中心格已揭开时拒绝使用并说明原因。

### 拆雷装置

- 能量消耗：2。
- 使用额度：1 次/层。
- 目标：已插旗的格子。
- 真雷：设置 `neutralized: true`，保留旗帜，工具成功消耗。
- 假旗：移除旗帜并直接揭开该安全格，随后执行正常洪水展开。
- 其他目标：拒绝使用，不扣除资源。

### 反应护盾

- 能量消耗：1。
- 使用额度：1 次/层。
- 目标：无目标，点击工具立即生效。
- 效果：本层下一次踩雷不扣生命，但仍会拆除该雷；同一时间只能有一个护盾。

资源消耗顺序固定为“确认目标合法 → 扣能量 → 扣工具次数 → 应用效果”，任何非法操作都不应改变棋盘、能量或次数。

## 强化与奖励

每层通关后生成三个互不重复的选项，玩家选择一个后立即应用。强化只在当前肉鸽局有效。

- `储能核心`：`maxEnergy + 1`，同时补充 1 点能量。
- `连锁能源`：连续安全揭开达到 3 次即可获得 1 点能量，并清零计数；替换基础的 4 次阈值。
- `医疗组件`：`maxLives + 1` 且 `lives + 1`。
- `工具增幅`：生成时绑定一种主动工具，下一层该工具的使用额度 `+1`；奖励卡片必须明确展示目标工具。
- `补给箱`：下一层三种主动工具各获得 `+1` 使用额度。

`工具增幅` 的三个绑定变体分别为 `工具增幅·侦察脉冲`、`工具增幅·拆雷装置` 和 `工具增幅·反应护盾`，它们在同一奖励界面中视为不同选项。若候选强化不足三个，使用尚未拥有的强化或绑定变体优先补齐；仍不足时以 `+1 energy` 作为兜底选项。奖励生成接收注入的 RNG，测试可以使用固定序列验证结果稳定且不重复。

## 模块边界

- `src/rogue-state.js`：创建运行状态、创建层状态、资源和状态转换的纯函数。
- `src/rogue-level.js`：五层参数、肉鸽棋盘生成、安全格统计和层初始化；复用现有八邻域棋盘生成能力。
- `src/rogue-items.js`：工具定义、强化定义、奖励候选生成和资源合法性判断；不依赖 DOM。
- `src/rogue-game.js`：肉鸽控制器，处理揭开、标记、工具、通关、受伤、奖励选择和重开，并提供 UI 所需的快照。
- `src/rogue-ui.js`：渲染肉鸽 HUD、棋盘、工具栏、奖励卡片和状态反馈；沿用 `src/ui.js` 的格子交互约定，不改变经典 UI 的行为。
- `src/app.js`：注册 `rogue` 模式，切换经典视图和肉鸽视图，将肉鸽控制器事件连接到 DOM。
- `src/config.js`：增加 `MODES.rogue` 和肉鸽展示常量，不改变既有难度表。
- `index.html`：增加肉鸽视图容器、HUD、工具按钮、奖励选择区域和模式入口。
- `src/style.css`：增加肉鸽布局、工具状态、生命/能量、已拆除雷和奖励卡片样式；主题变量沿用现有主题。

经典 `src/game.js`、经典 `src/ui.js` 的行为接口保持兼容；若必须抽取共用辅助函数，只允许新增纯模块并让旧调用路径保持不变。

## 用户交互

- 选择“战术扫雷”后显示肉鸽 HUD：层数、生命、能量、分数和当前强化。
- 肉鸽棋盘使用现有左键揭开、右键/长按循环标记、移动端标记模式和键盘导航。
- 主点击已揭开数字时继续执行快速展开；肉鸽模式下旗帜与问号规则不变。
- 工具按钮显示名称、快捷说明、能量消耗和剩余次数；不可用时置灰并提供 `aria-disabled`。
- 选择工具后显示目标提示，合法目标高亮；点击目标后清除工具选择。
- 生命变化、能量获得、雷被拆除、关卡通过和本局结束均写入 `aria-live="polite"` 的反馈区域。
- 奖励界面显示三个卡片按钮及其效果，支持键盘聚焦、Enter/空格选择，选择后回到下一层。
- 肉鸽结束界面提供“重新开始”按钮，不自动执行额外操作。
- 经典模式的提示、高亮、计时、最佳成绩和生成方式控件不受肉鸽状态影响。

## 测试要求

新增 `tests/rogue-minesweeper.test.js`，覆盖以下可观察行为：

- 初始运行状态为第 1 层、3/3 生命、2/3 能量和三种工具各 1 次。
- 五层参数按设计表生成，首点及其邻域安全。
- 安全揭开减少安全格数；连续安全揭开按阈值获得能量且不超过上限。
- 踩雷扣生命、雷变为 `neutralized`，同一颗雷再次操作不重复扣血。
- 护盾挡住一次伤害后消失，错误操作不消耗护盾。
- 拆雷装置对真雷和假旗分别执行正确效果；非法目标不改变资源。
- 侦察脉冲只返回区域雷数，不修改 `revealed`、`flagged`、`mine` 或 `neutralized`。
- 生命归零后不能继续揭开、标记、使用工具或选奖励。
- 清空安全格进入奖励或胜利；奖励选择只应用一个强化并进入下一层。
- 奖励选项无重复，固定 RNG 下结果稳定。
- 经典模式现有测试全部继续通过。

验证命令：

```text
npm test
node --check src/app.js
node --check src/rogue-game.js
git diff --check
```

## 非目标与后续扩展

动态雷区、冰冻格、传送格、视野限制、Boss、商店、金币、随机事件、永久成长、排行榜、种子和回放均不进入本次实现。后续若加入变化棋盘，必须作为明确的关卡词缀，并为其单独定义线索稳定性和测试规则。
