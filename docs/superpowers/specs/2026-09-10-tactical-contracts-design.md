# 战术扫雷：任务契约与特殊格设计规格

## 目标

在现有“战术扫雷”五层肉鸽流程上加入一层稳定、可解释的战术决策：每层开始先从两个任务契约中选择一个，完成契约后获得额外奖励；棋盘中加入情报点和补给点两类特殊格，并让现有三个工具与契约产生联动。

经典扫雷、偏移扫雷、Hex 扫雷、环形棋盘、数独扫雷、连连看和 3D 连连看的规则与入口保持不变。

## 当前基线

当前战术扫雷已经具备：

- 固定五层流程，棋盘从 7×7 逐步扩大到 11×14。
- 3 点生命、能量上限、踩雷后继续游戏的容错机制。
- 侦察脉冲、拆雷装置、反应护盾三个主动工具。
- 每层结束后的三选一强化。
- 移动端标记模式、键盘操作、ARIA 标签和焦点恢复。
- 工具选中后可再次点击取消；工具成功使用后会自动取消选中。

当前不足是：关卡目标仍然只有清空安全格，工具更多是一次性补救，任务之间缺少取舍，肉鸽层与扫雷层的决策联系还不够紧密。

## 设计边界

本期只改 `rogue` 模式：

- 保留五层、生命、能量、工具和三选一强化。
- 不改变经典扫雷的雷数、首点安全、洪水展开、标记和快速展开规则。
- 不加入动态重新布雷、商店、金币、地图分支、Boss、持久化成长、种子或回放。
- 不让特殊格变成雷，不改变数字线索的计算方式。
- 特殊格的效果只在战术模式中生效。
- 每层契约只选择一个；契约奖励最多结算一次。
- 契约失败不立即结束关卡，玩家仍可正常完成该层并领取普通关卡奖励。

## 核心流程

### 关卡状态

沿用现有 `status`：`ready`、`playing`、`reward`、`won`、`lost`。不新增顶层状态，避免破坏现有路由和结果处理。

在 `ready` 状态下增加契约选择子状态：

1. 创建下一层空棋盘和两个契约选项。
2. 棋盘格、工具和标记操作在契约选择完成前均返回 `invalid`。
3. 玩家选择一个契约后，记录为当前层契约，清空另一个选项，并允许首次揭开。
4. 首次揭开后沿用现有首点及邻域安全规则，棋盘正式进入 `playing`。
5. 每次揭开、踩雷、使用工具、触发特殊格时更新契约进度。
6. 契约达成时立即标记完成并发放一次契约奖励；需要等到关卡结束才能判断的契约，在清空安全格时结算。
7. 清空安全格后仍进入原有的普通三选一强化流程；契约奖励不替代普通强化。

### 运行状态数据

在肉鸽运行状态中增加当前契约字段，字段使用普通 JSON 数据，不保存函数：

```js
contractOptions: [],
selectedContract: null,
contractProgress: 0,
contractTarget: 1,
contractCompleted: false,
contractRewardGranted: false,
levelStats: {
  damageTaken: 0,
  safeReveals: 0,
  toolsUsed: {},
  trueMinesDefused: 0,
  shieldedHits: 0,
  specialCellsCollected: 0,
},
```

`levelStats` 在每层创建时清零；`selectedContract`、进度和奖励状态只属于当前层。已有 `upgrades`、`energy`、`lives`、`score` 和 `nextLevelToolBonus` 继续沿用。

## 任务契约

新增独立的 `src/rogue-contracts.js`，负责契约定义、选项生成、进度目标和奖励描述。控制器只负责派发事件和保存结果，避免把规则堆进 `rogue-game.js`。

### 契约池

第一版使用四种固定契约。每层从中随机抽取两个不同选项；抽取使用注入的 RNG，测试可确定复现。

| ID | 名称 | 完成条件 | 契约奖励 |
| --- | --- | --- | --- |
| `noDamage` | 零误触 | 本层清空安全格时 `damageTaken === 0` | 当前能量 +1，不超过上限 |
| `reconnaissance` | 情报回收 | 成功触发或扫描一个情报点 | 下一层侦察脉冲使用次数 +1 |
| `controlledDemolition` | 精准爆破 | 使用拆雷装置成功拆除一颗真雷 | 下一层拆雷装置使用次数 +1 |
| `reservePower` | 节能推进 | 本层清空安全格时至少保留 1 点能量 | 当前分数 +10，并获得 1 点安全连击进度 |

契约文案必须同时显示目标、当前进度、奖励和失败条件。不可把概率判断、猜测正确或“尽量少踩雷”作为契约条件；所有条件必须能由控制器确定记录。

### 选项与选择规则

- `getContractOptions({ floor, rng })` 返回两个不同的契约定义副本。
- 选项顺序由注入的 RNG 决定，同一 RNG 下结果稳定。
- 选中的契约立即进入 `active` 语义；不支持重新抽取或反悔。
- 契约选择按钮可用键盘操作，选择后焦点回到当前棋盘焦点格。
- 在契约选择前，棋盘格和工具按钮必须显示为不可用；选择后恢复普通可用状态。

### 进度结算

控制器通过明确事件更新契约：

- `safeReveal(count)`：累加 `levelStats.safeReveals`，不直接完成上述四种契约。
- `mineHit({ shielded })`：累加 `damageTaken`；护盾成功抵挡时累加 `shieldedHits`。
- `toolUsed({ toolKey, success, targetSpecial })`：累加对应工具使用次数；拆雷真雷时累加 `trueMinesDefused`。
- `specialCollected(type)`：累加特殊格收集数；情报点可完成 `reconnaissance`。
- `levelClear`：判断 `noDamage` 和 `reservePower`。

契约完成检查必须幂等：同一契约即使收到重复渲染或重复事件，也只能发放一次奖励。

## 契约奖励

契约奖励是自动发放，不再增加第二个奖励选择界面：

- 能量奖励：`energy = min(maxEnergy, energy + 1)`。
- 工具增幅奖励：增加 `nextLevelToolBonus`，只影响下一层初始工具次数。
- 分数奖励：直接增加 `score`。
- 安全连击奖励：将 `safeRevealStreak` 增加 1，但仍受现有能量上限和连锁强化规则约束。

奖励发放后 `contractRewardGranted` 设为 `true`，并在 `notice` 中说明契约名称和奖励。若当前关卡同时完成并进入普通 `reward` 状态，提示文案需要合并，不能覆盖普通三选一提示。

## 特殊格

### 数据结构

在战术棋盘格上增加：

```js
special: null | "intel" | "supply",
specialCollected: false,
```

特殊格永远不是雷，不参与雷数计算。经典模式使用的普通 cell 数据不增加这些字段也必须能够正常工作。

### 生成规则

在首次点击生成普通雷区后，再从安全格中放置：

- 每层最多一个情报点和一个补给点。
- 默认排除首点及其八邻域，避免开局洪水直接吞掉全部特殊格。
- 候选不足时从剩余安全格中补足；无法放置时允许该类特殊格缺席，但关卡仍必须可玩。
- 放置特殊格不移动雷、不改数字、不破坏首点安全。
- 使用注入的 RNG 打乱候选位置，测试可验证位置合法而不依赖固定坐标。

隐藏格的辅助标签需要包含特殊格类型，例如“第 3 行第 4 列，情报点，未揭开”；视觉上使用独立但低干扰的图标或边框。特殊格揭开后保留图标，并在已收集状态下提供明确的 ARIA 描述。

### 情报点

玩家揭开情报点，或使用侦察脉冲准确选择情报点时，触发一次情报回收：

- 显示该点周围裁剪后 3×3 区域的雷数。
- 标记情报点已收集，完成 `reconnaissance` 契约。
- 普通揭开触发情报点不消耗能量或工具次数。
- 侦察脉冲选择情报点仍按现有工具规则消耗一次工具和能量，但额外完成契约；不改变棋盘字段。
- 情报点效果只触发一次，洪水展开经过该点时也必须幂等。

### 补给点

玩家揭开补给点时触发一次补给：

- 当前能量 +1，不超过上限。
- 在工具剩余次数最少的工具中补充 1 次；平局按侦察脉冲、拆雷装置、反应护盾的顺序选择。
- 标记补给点已收集并在 `notice` 中说明获得的资源。
- 补给点不直接完成契约，但会影响节能推进和工具联动的决策。
- 补给点效果只触发一次，洪水展开经过该点时也必须幂等。

## 现有道具联动

本期不删除或改变三个工具的基本用途，只增加可观察的契约联动：

- 侦察脉冲扫描情报点时完成情报回收契约；扫描普通格的行为和资源消耗保持不变。
- 拆雷装置成功拆除真雷时完成精准爆破契约；拆穿假旗不算完成。
- 反应护盾成功抵挡踩雷时记录 `shieldedHits`，为后续契约扩展保留事件数据；本期不新增专属护盾契约。
- 使用工具前后仍然遵循现有资源原子性：无效目标不消耗能量、次数和契约进度。
- 道具按钮仍支持再次点击取消、点击其他道具切换、Escape 取消和键盘操作。

## UI 设计

在 `rogueView` 中新增契约区域：

- `rogueContractPanel`：契约容器。
- `rogueContractOptions`：两个契约选择按钮。
- `rogueContractProgress`：当前契约名称、进度、奖励和完成状态。

交互要求：

- `ready` 且未选择契约时显示两个契约卡片，棋盘和工具置灰。
- 选择后隐藏选项卡，显示当前契约进度。
- 契约完成后显示“契约完成”和奖励，不阻塞继续扫雷。
- 契约未完成时，在关卡结束提示“本层契约未完成”，但仍进入普通奖励流程。
- 情报点和补给点在隐藏、揭开、已收集三种状态下都有不同的 class 和 `aria-label`。
- 所有提示使用现有 `aria-live="polite"` 区域，不弹出阻断式对话框。
- 重置、进入下一层、切换离开战术模式时清理临时契约焦点和工具选中状态。

## 模块与数据流

```text
createRogueRunState
        ↓
createLevel → generateClassicBoard → placeSpecialCells
        ↓
getContractOptions → rogueContractPanel
        ↓ 选择一个契约
reveal / cycleMark / tool
        ↓
事件更新 levelStats → 检查契约 → 发放一次奖励
        ↓
清空安全格 → 契约结算 → 普通三选一强化 → 下一层
```

建议的模块边界：

- `src/rogue-contracts.js`：纯契约定义、抽取和文案。
- `src/rogue-level.js`：特殊格放置和特殊格数据初始化。
- `src/rogue-game.js`：契约选择、事件记录、特殊格触发、奖励结算。
- `src/rogue-ui.js`：契约区域、特殊格呈现和交互禁用状态。
- `src/rogue-state.js`：默认契约和每层统计字段。
- `src/app.js`：只增加战术模式的 handler 和渲染绑定，不改经典模式分支。

## 测试范围

新增或扩展 `tests/rogue-minesweeper.test.js`，至少覆盖：

- 每层契约选项恰好两个、互不重复、注入 RNG 后稳定。
- 未选择契约前，揭开、标记和工具操作均无状态变化。
- 选择契约后可以正常首次揭开并进入 playing。
- 四种契约分别在正确条件下完成，在错误条件下不完成。
- 契约奖励只发放一次，且不会突破能量或生命上限。
- 情报点和补给点只放在安全格，不改雷数和数字。
- 首点及邻域不会放置特殊格；候选不足时仍能创建合法关卡。
- 情报点普通揭开、洪水展开和侦察脉冲联动均只触发一次。
- 补给点能量和工具补给按确定优先级生效。
- 无效工具目标不消耗资源，也不推进契约。
- 当前层契约状态在选择奖励进入下一层时正确重置。
- 契约完成后仍能继续扫雷；未完成契约仍能领取普通关卡奖励。
- 生命归零、通关后和奖励选择期间不能通过契约或特殊格继续操作。
- 现有经典、偏移、Hex、环形、数独、连连看和 3D 连连看测试继续通过。

## 非目标与后续

本期明确不实现：

- 动态重新布雷、传送格、冰冻格、视野迷雾。
- 契约重抽、契约升级、商店、金币和地图分支。
- 特殊格随机连锁、概率提示或自动替玩家操作。
- 种子、回放、排行榜和持久化肉鸽局。

后续可以在本期数据结构稳定后，再增加精英契约、事件层和分支路线；这些都必须作为独立设计，不在本期顺带加入。

## 验收标准

- 每层开始玩家能看到两个不同契约，并且必须选择一个后才能操作棋盘。
- 情报点和补给点能在战术棋盘中被识别、触发一次并显示结果。
- 至少一个契约需要使用现有工具才能高效完成，工具选择会影响任务取舍。
- 契约完成奖励与普通三选一强化同时存在且互不覆盖。
- 战术模式的失败、通关、重置和切换入口正常。
- 经典及其他玩法行为不变。
- `npm test`、语法检查和 `git diff --check` 全部通过。
